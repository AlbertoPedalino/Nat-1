# Project Memory

GM-Board is React 19 + Vite + MUI 9 + Supabase SPA under `react-app/`. D&D data loads at runtime from 5etools mirrors; never vendor source JSON or image assets.

## Project Rules

- Data repo: `https://github.com/5etools-mirror-3/5etools-src/tree/main/data`.
- Encounter image assets currently use mirror-2; Skeleton fallback uses mirror-3 XMM token URL.
- Allowed sources: `XPHB`, `XMM`, `XDMG`, `FRAIF`, `FRHOF`, `EFA`, `RWH`.
- Raw mappings: `FRAIF -> FRAiF`, `FRHOF -> FRHoF`, `RWH -> RHW`.
- Reject legacy, unofficial, homebrew, and non-whitelisted sources unless explicitly mapped.
- Prefer minimal scoped changes. Do not commit `.agent-loop` artifacts unless requested.

## UI Conventions

- Dark-only fantasy theme: `src/app/theme.js`.
- Use MUI `sx` and theme tokens; no new CSS, `styled()`, inline `style`, or component color literals.
- Existing `pages/library/styles.js` contains legacy literals; do not spread them.
- Icons: `lucide-react`.
- Entity tinting: `shared/ui/entityColors.js`.
- Toasts: `ToastProvider` / `AppToast`.
- Application routes/theme: `src/app/`; navigation: `src/app/navigation/`; reusable presentation primitives/hooks: `src/shared/ui/`; page-specific UI: page feature folder.
- Use responsive `sx`; theme radius is 8.
- Font sizes are steps of `FONT_SIZES`, letter spacing of `LETTER_SPACINGS` (both `shared/ui/fonts.js`, guarded); never a literal rem/px/em. Box-relative clamps (cqmin) and em sizes stay local.
- Sheet row detail panel + gold title: `detailPanelSx`/`detailTitleSx` in `pages/charsheet/layout/layout.js`.
- Control looks live in `app/theme.js` components: Button sizes/outline, OutlinedInput outline, Tooltip (raised surface), selected states (`SELECTED_OPTION_SX` for ToggleButton, `SELECTED_ROW_SX` for ListItemButton/MenuItem; local `'&.Mui-selected'` guarded out, use `:not(.Mui-selected)` for resting colours). Page sx only places/sizes controls.
- Text treatments are `TEXT_STYLES` roles (`shared/ui/textStyles.js`): `label` (Cinzel small caps), `title` (Cinzel spaced), `figure` (Cinzel numbers/values), `note` (italic aside). Spread first, size/colour local: `{ ...TEXT_STYLES.label, fontSize: FONT_SIZES.xs }`. Guarded.
- Colours are named by role (`accent`, `accentText`, `textMuted`, `surfaceHeader`, `danger`, `<role>Text`, `on<Role>`), never by hue (guarded in `tests/logic/shared/vtt/colors.test.js`). `VTT_COLORS` interface roles read `UI_COLORS`; theme `gmboard` status groups too. Tiers/rarity/entity/effect colours are data.
- More scales (all guarded in oneDefinition.test.js): opacity `OPACITY` (`shared/ui/colors.js`: faint…solid, for every alpha/uiAlpha/vttAlpha, chip tint and CSS opacity); surfaces `SURFACES` (`shared/ui/surfaces.js`: panel, inset, wash, map, mapControl — spread first, add layout); spacing in theme units, quarter steps, never px; `FONT_WEIGHTS` and `LINE_HEIGHTS` (`fonts.js`); `ICON_SIZES` (`shared/ui/iconSizes.js`) for lucide `size`; app-wide stacking `LAYERS` (`shared/ui/layers.js`).
- Meaning palettes stay independent of UI_COLORS by user decision (2026-11-09), even where a hex matches a role: `ENTITY_COLORS`, `ACTION_COLORS`, `DAMAGE_TYPE_COLORS` (also the source of `VTT_COLORS.area*`), rarity/tier. Non-entity neutral gold = `UI_COLORS.accentText` (`NEUTRAL_TONE` removed). One pick-a-colour palette `SWATCH_COLORS` (`shared/ui/swatches.js`) for players, combat labels, imported tokens, icon picker. Map HP/temp-HP bar tones are `darken()` of the UI status roles. A result with no tone falls back to `gmboard.result.none`, never `rarity.Common`.
- Small heights (tags, badges, compact rows/controls, toolbar fields) are `CONTROL_HEIGHTS` steps (`shared/ui/controlHeights.js`, 16–40px); small chips are 20px from the theme (`MuiChip.sizeSmall`). Shapes sized to themselves (round swatches, colour bars, avatars, square icon buttons) keep their own. Transition times are `DURATIONS` (`shared/ui/motion.js`: fast 120, normal 160, slow 220; guarded); dice keep their own rhythm.
- Tag rule (user, 2026-11-09): `MiniBadge` (`shared/ui/MiniBadge.jsx`, small rectangular, tints itself with its colour at `OPACITY.fill` unless `bg` is given) = an attribute of a row (source, level, cast time, C/R, item/action tags, class Hit Die/saves, background grants, score breakdown) on sheet and builder alike; MUI `Chip` = info that stands alone or is clicked (counters, filters, conditions, states, read-only). Coloured chips are tinted only through `chipTintStyle`. Tag builders (`actionTags`, `buildItemTags`, `getSpellStatusChips`, `SpellMiniTags`) return `{ key, label, color }`, no `bg`.
- One theme for the whole app (guard: `createTheme` only in `app/theme.js`). No page-wide size layer: the builder's old `builderDensity.js` (`:where()` rules) lost to the theme's variant styles and was removed (2026-11-11). Builder panels = `BuilderPanel` → shared `PanelHeader` + `panelBodySx`, the sheet's panel; preview sections the same; text by role from `pages/charbuilder/layout/builderText.js` (`BUILDER_TEXT`: panelTitle, boxTitle, sectionHeader, cardTitle, groupLabel, note, hint, body, value, itemName, itemMeta — the sheet's roles a step larger; plus displayTitle, stepTitle, caption, figure, chip, chipLabel; PanelHeader takes `titleSx`) — no `fontSize` and no body/caption text variant anywhere else in pages/charbuilder (guard in builderHeadings.test.js); only the page title and app bar use h1/h2 (guard in `tests/logic/pages/charbuilder/builderHeadings.test.js`). Headings h1/h2 and tabs use the title role; outlined inputs share `surfaceHeader`.
- Radii are multiples of the theme radius (sx numbers; `cornerRadius` in `shared/ui/radius.js` per corner); surface drop shadows are `UI_SHADOWS` (`shared/ui/shadows.js`: raised/float/popup/overlay). Both guarded.
- `theme.palette.gmboard.badge.cloud` owns cloud-origin badge color.
- `react-window` is reserved for new lists expected to render hundreds of rows.

## Source Code Layout

- Structure guides: `react-app/src/README.md` and `react-app/src/shared/README.md`. Group shared modules by responsibility; keep imports direct rather than adding compatibility barrels at retired paths.
- `shared/character/`: `combat`, `dice`, `forms`, `inventory`, `profile`, `progression`, `resources`, `spells`. Domain components stay beside their rules.
- `shared/content/`: entry rendering, 5etools links, source filtering/priority, text search. These are shared by multiple tools, not specific to character sheets.
- `shared/ui/`: generic components/hooks, toast provider, entity colors, route titles.
- `shared/instances/`: the tool-instance layer shared by GM Board, Encounter Builder and DM Screen (see Tool Instances). `shared/storage/`: generic localStorage helpers and character registry metadata.
- `shared/cloud/`: `api` for resource operations, `auth` for authentication/account UI, `sync` for autosync/realtime. The common `supabaseClient.js` stays at the cloud root.
- `shared/vtt/`: `map`, `scene`, `session`, `tokens`, `sheets`, `rolls`; palette stays in `colors.js`. `shared/campaign`, `dungeon`, and `hexcrawl` retain their compact domain structure.
- Large pages group related components, hooks, styles, and logic together by feature. VTT: `scene`, `map`, `tokens`, `objects`, `atmosphere/shaders`, `sheets`, `rolls`, `session`, `dungeon`, `hexcrawl`. Character sheet: `actions`, `spells`, `inventory`, `forms`, `resources`, `stats`, `proficiency`, `details`, `layout`, `state`.
- Builder, encounter builder, GM Board, and DM Screen follow the same feature grouping; see the source guide for their folder maps. Small pages retain their compact layout. Existing cross-page dependencies and adapter discovery remain unchanged; deleted charbuilder barrels must not be recreated.
- Keep `src/` free of tests and empty placeholder folders; tests mirror source categories under `tests/logic` and `tests/ui`.

- `InstanceRow` lacks a wrapper `aria-label`, preserving child accessible text.
- Route-param picker reuse may briefly retain prior rows until async refresh completes.

## Linked Tool Groups

- GM Board, Encounter Builder, and DM Screen instances can share an explicit random `linkGroupId`; names never create links.
- Local registries store `linkGroupId`; Supabase rows store `link_group_id` with `(owner, link_group_id)` indexes.
- `app/navigation/LinkedToolsMenu.jsx` lists linked instances, links existing saves, creates linked tools, merges groups after confirmation, and unlinks members.
- Groups can contain multiple instances of any supported tool type.
- Opening a linked instance uses a React Router link with `target="_blank"` and `noopener noreferrer`; the new tab opens it through `useToolInstance` (cloud-first for an id unknown there).
- Link management is always available on an open tool page (its instance exists locally). A local copy is relinked locally (link dirty) and synced with `ensureInstanceInCloud` before a campaign may reference it; a cloud-only row is relinked with `linkCloudInstance`.
- `?<param>=new&linkGroup=<id>` creates the instance with that group.
- Re-run `supabase/02_sections.sql` on existing projects to add `link_group_id` and its indexes.

## Battle Map / VTT

- Root/entry: `src/pages/vtt/VttPage.jsx`; scene orchestration: `scene/SceneEditor.jsx`; rendering: `map/SceneViewport.jsx` / `tokens/TokenSprite.jsx`.
- `/vtt` shows the scene/table picker; `/vtt?scene=<id>` requests a scene directly; `/vtt?campaign=<id>` follows that campaign's live scene via `shared/vtt/session/useLiveSession.js`. Campaign-following takes precedence if both parameters exist. VTT requires configured cloud access and authentication; scene permissions still come from Supabase and `shared/vtt/session/useSceneRole.js`.
- Projector links are `/vtt?campaign=<id>&spectator=<cameraSource>`, built by `shared/vtt/session/spectator.js` from the current URL so the deployment base survives. They replace scene/query selection, require both campaign and a valid presenter source, and follow live-scene changes. Battle-map cloud operations are one module per resource in `shared/cloud/api/` (import from the owner, no barrel): `vttScenes.js` (scene rows, live scene, delete), `vttSceneTurns.js` (shown fight), `vttScenePictures.js` (replace/remove battlemap, add/remove backgrounds), `vttTokens.js` (pieces + `map_token_secrets` labels/HP), `vttDrawings.js`, `vttMapImages.js` (Storage upload, signed-URL cache, cleanup); tests mock the owning module. Scene realtime state in `shared/vtt/session/useSceneLive.js`.
- Fog strokes sweep a round brush along fractional fog-cell coordinates between pointer events, so fast diagonal motion has no gaps. Each new drag resets its previous point. `FogCanvas` adds a light blur proportional to the fog-cell size, zoom, and device pixel ratio. Saved fog bitsets and resolution remain compatible; regressions cover reveal/hide, fast motion, and separate strokes.
- Grid offsets (2026-10-27, user report: hex map cut after reopening): `normalizeGrid` keeps offsetX/Y exactly as calibrated. The old fold into one square moved every cell-relative position by a cell on reload and broke hex alignment (hex rows repeat every √3 × size). Fog alone anchors at `fogOrigin(grid)` (offset folded by one square) so saved fog never moved. Play-area fit is `playAreaForImage` (`geometry.js`: squares touching the picture / hexes whose centre is on it); `SceneEditor.handleGridChange` refits an area that matched the fit for the old grid, custom areas untouched.
- Stale scene rows (2026-10-28, user report: grid size/line width/refit snapping back): local edits never move `scene.updatedAt` and pending echoes are refused, so a recovery read started before the write (it waits on the whole reconcile) or an earlier write's echo used to be accepted afterwards. `SceneEditor` keeps `savedRevisionRef` (updatedAt returned by our own `updateScene` writes via `noteSceneWrite`); `acceptsScene` refuses rows older than it or than the held scene.
- Fog rendering covers the entire viewport and erases only revealed cells using a blurred `destination-out` mask. Never blur the outer covered rectangle: that exposes the map perimeter. Grid-offset margins and areas beyond old fog dimensions stay covered; fill the complete rounded-up backing store before applying view transforms so fractional device pixel ratios cannot leave a translucent edge.
- Atmosphere must remain visible in Player view and on the projector even over unexplored fog. Public fog, atmosphere, then rulers/lasers share z-index 4 in that DOM order; controls stay higher. Atmosphere's WebGL canvas and static fallback use the same layer. Never raise hidden map pieces above fog to fix weather visibility.
- The right tool rail has an explicit cursor tool. Selecting draw, erase, text, fog, ruler, or laser activates that behavior immediately; laser stays active until another tool is selected. While any non-cursor tool is active, the entire token/object interaction subtree becomes pointer-transparent, so the selected tool can start directly over a piece; token drag, resize, death-save dots, pills, and context menus return only with the cursor tool.
- Scene bar and rail layout (user requests 2026-11-04): Rolls is a round dice icon (no label, tooltip/aria "Rolls") on the map's top-right corner, just left of the tools toggle (user requests 2026-11-04, it was a labelled button in the middle of the scene bar): `rolls/RollsButton.jsx` (popover with `RollLogPanel`) passed as `SceneViewport` `rolls`, in one row `cornerButtonsSx` with the fullscreen Sheet button and the toggle; round icon look shared as `mapIconButtonSx` in `map/battleMapSurface.js`. - A GM-only projector mode opens a campaign-bound spectator view whose only control is the bottom-right fullscreen button. It is started explicitly from the compact scene-actions menu, independently of `Go live`; only after that opt-in do the projector controls appear. Whether a projector is attached is owned above the scene editor: the window handle lives in `VttPage` (`projectorWindowRef`, like the camera source), so going back to Tables or into another scene keeps it, and after a GM-page reload the projector announces itself over a same-browser `BroadcastChannel` keyed by the camera source (`shared/vtt/session/projectorLink.js`: `who`/`here`/`gone`/`close`; the projector side answers from `VttPage`, the presenter asks on mount and on window focus). `Projector mode` is therefore never offered over a running projector (it used to be, and opened a second window, fixed 2026-10-14); `Stop projector mode` closes by handle and by message. The GM-window camera source lives in per-tab `sessionStorage`, survives refresh and scene-editor remounts, and is re-announced when realtime reconnects. - The scene header is a compact translucent battle-map surface: scene title and stats form one identity block, role is a small badge, GM live/projector actions are grouped, and the Map/Sheet switch is aligned as the final control with responsive wrapping.

## Tool Instances

GM Board, Encounter Builder and DM Screen share one local-first model in `src/shared/instances/`; a tool only provides its payload adapter (`pages/<tool>/state/storage.js`: keys, (de)serialization, tool-specific no-op checks such as the Encounter draft's `updatedAt`).

- `instanceStore.js` (local repository): registry entries `{ id, name, updatedAt, linkGroupId, cloud: local-only|linked|conflict, version, conflict, dirty: { data, name, linkGroup }, rev }`. `saveLocal(section, id, values)` is the only write path: unchanged values are skipped (no dirty mark, no notification), a write for an unlisted id registers it, failures roll back. `listInstances` normalizes legacy entries (`pendingInsert` -> local-only, `namePending`/`linkGroupPending` -> dirty) and re-lists ids whose data exists without an entry (local-only). No cap. In-process feed: `subscribeInstances` / `subscribeInstanceData` (replaces the old `gb:*-saved/deleted` window events).
- `instanceCloud.js`: the only Supabase path (`boards`, `encounters`, `dm_screens`): `fetchMeta`, `fetchRow`, `listRows`, `insertRow` (INSERT only; 23505 -> duplicate), `updateData` (`where version = N`), `updateMeta` (name/link), `deleteRow`. No upserts.
- `version bigint not null default 0` (`supabase/18_section_versions.sql`) is the only concurrency token. A `before insert or update` trigger owns it: INSERT -> 0, UPDATE changing `data` -> old + 1, name/link-only UPDATE -> unchanged; it also sets `updated_at` (server time on data changes, otherwise unchanged) and ignores client values for both. `updated_at` is only for sorting/display. Stored local versions that are not non-negative integers (older formats, including the interim timestamp versions) normalize to null and are verified by data equality before any write. The VTT's board freshness check (`readHexcrawlBoardVersion`) reads `version` too.
- `instanceSync.js` (engine): local-only -> INSERT, duplicate -> conflict `exists`; linked + data dirty -> UPDATE `where version = N` (the database returns N+1, adopted locally), 0 rows -> conflict `version` (another tab's newer version -> retry; row gone -> re-INSERT); name/link only -> metadata update; legacy linked without version -> adopt the row if its data is identical, else conflict `unverified`. Settling adopts the cloud name/link unless dirty; edits made during a sync stay dirty (`rev`). Conflicts write nothing until `resolveConflict('cloud' | 'local')`. Also `openInstance`, `refreshInstance` (fast-forward a clean linked copy), `pullInstance` (keeps dirty name/link), `renameCloudInstance`/`linkCloudInstance` (cloud-only rows), `ensureInstanceInCloud`, `deleteInstance`, `listToolInstances`, `mergeInstanceRows`, `flushInstances`.
- `useToolInstance(sectionKey)` (the page hook): resolves the URL (`new` mints, no param reopens the active instance), opens known local copies at once (linked ones refreshed in the background), makes unknown ids wait for auth then asks the cloud (pull / create / offline stand-in that can only INSERT), exposes `ready`, `revision` (provider key; bumped by pulls), `conflict`, `resolveConflict`. `InstanceConflictBanner` shows the choice; `CloudInstanceLoading` the wait.
- Persistence hooks hydrate once (a `hydrated` state flag makes the first write happen from the post-hydration render) and then save every change; a new instance's first save is its seed.

## Gotchas

- New directories may be absent from ordinary unstaged diff.
- Hydration effects key on instance id; saving must not rehydrate fresh state.
- Mirrored local state can overwrite hydrated values.
- MUI layout props can leak to DOM; keep layout values in `sx`.
- Button descendants must remain phrasing content.
- Wrapper `aria-label` replaces subtree accessible text.
- Guard object lookups with `hasOwnProperty.call`.
- Testing Library regex names are substring matches.
- Synchronous localStorage reads should use lazy state initializers.
- Avoid bulk line-ending rewrites.
- Animated overlays (atmosphere + area effects, 2026-10-20): fragment shaders use `highp` when `GL_FRAGMENT_PRECISION_HIGH` (mediump = fp16 on phones/tablets: time and hash noise broke into steps/blocks, the "weather flickers on a player's app" report). Time comes from `shaderSeconds()` (AtmosphereOverlay.jsx): page clock, wraps after 4 h; the old `Date.now()/1000 % 4096` (area: `% 600`) made every effect jump to another frame at each wrap. WebGL contexts (2026-10-20, user report: weather broke once in an evening, fixed only by switching it off and on): both overlays key their canvas (`useContextRecovery().generation` in `atmosphere/webglCanvas.js`), give the context back on cleanup (`releaseContext` → WEBGL_lose_context; the cleanup must only run when the canvas goes, so the key carries every effect dependency), and on `webglcontextlost` remount a fresh canvas after 400 ms; >3 losses in 30 s → static fallback (atmosphere) / no animation (areas). Cause: browsers keep few contexts (fewer on mobile) and evict the oldest; unreleased contexts from remounted canvases piled up.
